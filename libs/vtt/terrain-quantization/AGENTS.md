# AGENTS.md -- `grafting-vtt-terrain-quantization`

Scope-local addendum to the root `AGENTS.md`. Root rules still apply.

This crate is a Wasm bridge only, mirroring `libs/vtt/generation-wasm` and
`libs/isekai/wasm-bridge`'s own boundary discipline: it exposes a thin
typed-array ABI to the Web host and must not accumulate unrelated domain
logic. Its current single function, `quantize_heightmap`, is deliberately
scoped to pipeline step 3 (quantization into the discrete grid) from
`docs/research/vtt-map-and-terrain-construction-options.md` — it must not
grow into the terrain-WFC tileset pass, water-mask integration, or
building/interior-generation passes described there; those belong in their
own crate(s) once designed, not bolted onto this one.

Panics are not catchable on `wasm32-unknown-unknown` (no `catch_unwind`),
the same constraint `libs/isekai/wasm-bridge/AGENTS.md` and
`libs/vtt/generation-wasm/AGENTS.md` already document for their own crates —
validate inputs at the boundary rather than relying on panic recovery
(`quantize_heightmap` clamps rather than panicking on out-of-range input or
a `levels` of 0, deliberately, for exactly this reason).

Consumed by `apps/architecture-studio`'s `/lab/terrain-quantization` route
as a normal `workspace:*` dependency on this crate's own co-located
`package.json` (`@grafting/vtt-terrain-quantization`) -- not a separate
generated npm wrapper. Do not depend on this crate from anywhere in
`libs/isekai/` or `libs/engine/` — this is a VTT-product-specific crate
(DEC-046), not a shared engine domain.

Per DEC-055/ADR-0017: `pkg/` (this crate's own `wasm-pack` output,
generated by this package's `postinstall` script) is gitignored and MUST
NOT be committed. Do not reintroduce a separate
`packages/vtt-terrain-quantization` technical package.
